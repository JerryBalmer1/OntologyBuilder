Ontology Builder — strawman taxonomy

Two axes: where a thing sits (layer, vertical) and what it does (role, horizontal). Everything here is a first guess to argue with. Once agreed, it becomes config/layers.yaml and config/roles.yaml, and the agent works against those, not prose.

The stack — infrastructure is the floor

Each tier binds downward to the one below it. Solve the bottom tier, expose outputs, then the next tier becomes a smaller problem. Only the bottom tier is in scope now; the rest are named so the config has somewhere to put them later.

AI & agentslater

The role axis — substrate vs everything that leans on it

A provider's role is mostly decidable from the direction its references point. Substrate providers get referenced; support providers do the referencing and rarely contain anything.

RoleWhat it isExample providers
Substrate Owns the things that physically or virtually exist. Has containment.Tell: high fan-in. Many types reference it; it references few outside itself. azurerm aws google vsphere proxmox
Orchestration Builds, deploys, schedules. Has its own internal hierarchy (org → project → pipeline) but that hierarchy contains no infrastructure.Tell: references substrate via "agent pool", "environment", "service connection". azuredevops github gitlab
Observability Watches things. Never creates the host it monitors.Tell: references outward only. Zero containment of substrate types. datadog newrelic grafana
Security & secrets Gates access, holds credentials. Attached to substrate, not part of it.Tell: references identity-layer types; vocabulary is "policy", "role", "secret". vault okta azuread
Data services Managed databases, queues, caches. Ambiguous — a managed Postgres is compute+storage the vendor hides.Open question: is this a role, or is it compute inside the substrate? azurerm_postgresql_* aws_rds_* mongodbatlas
Edge / delivery CDN, DNS, WAF. Sits between the world and your network.Open question: networking layer, or its own role? akamai cloudflare

Containment is a first-class relationship

How the agent would derive this — proposed rules

Ordered. First rule that fires wins. Everything inferred is tier 4 and says so, so a wrong guess is visible instead of baked in.

1
If config/layers.yaml names the type explicitly, use that.Declared beats inferred. This is where you correct the algorithm.
2
Containment from fan-in: if >N% of a provider's types reference type X through an attribute named like *_group_name, *_id, parent_*, X is a container and the edge kind is contained_by, not references.Resource group, subscription, datacenter, folder, VPC all fall out of this.
3
Provider role from reference direction: a provider whose cross-provider edges are all outbound and which has no contained_by edges into substrate types is a support service.Datadog, Grafana, Vault land here without a keyword rule.
4
Layer from vocabulary in the docs: network, subnet, vpc, route, nsg, port group → networking; disk, bucket, datastore, volume, blob → storage; vm, instance, cluster, node pool, scale set → compute.Same mechanism as Get-CategoryRuleSet, different axis. Move both to config.
?
Anything a support provider references that doesn't resolve to a substrate node becomes a placeholder node, tier 4, waiting to be joined.Datadog doesn't declare the host, but the host exists.

Things to argue about

Is identity a layer or a role? Are data services compute, or their own thing? Is edge/CDN networking? Where does azuread go — it's substrate for Azure but reads like security. Does the fan-in threshold need to be per-provider? None of these need answering before the config exists; they need answering before it's trusted.
