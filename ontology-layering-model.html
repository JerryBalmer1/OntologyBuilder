Layering model and vocabulary

Ontology Builder — the battle plan in visual form. Human-readable here; machine-readable in the JSON block at the end of the file. Same model, one file.

How to read this document

Every bordered box is a named container. Inside a container, the bottom item holds the most weight: everything above it depends on it and cannot exist until it is in place. Read bottom-up. The item with the heavy border is the ground of that container. A container's name is always shown in the same colour, wherever it appears, so Knowledge in a table means the same thing as the Knowledge box in the diagram.

The one-line version

Schema is the ground. Without it there is no discovery, no state, no action — nothing. Infrastructure is the floor of the Stack, and networking is the floor of infrastructure. Every level, and every level inside a level, runs the same four Rungs. The model is fractal: build the mechanism once, point it at each domain.

Two kinds of structure

Stack
Things that genuinely rest on each other. Modelled as containment and dependency edges.
Cross-cutting
Things that attach at every level rather than sitting between two of them. Modelled as labels on nodes, never as a layer. Test: if putting it in the Stack means it has to sit between two floors and nothing rests on it, it is not a floor. It is a role.
DimensionsThree independent labels on every node
A dimension is one axis a node can be positioned along, independently of the others. Same node, three labels, filter on any one. Order: derivation order — the bottom one is available first and the others build on it.
Business contextWho owns it, how much does it matter — cost centre, service owner, criticality, compliance scope. Later. Slots in with no refactor.
needs a typed, placed node ↓

needs the schema ↓

Glossary

Ontology
The containment chains and edge kinds — actual relationships between real kinds of things. In this repo, the Schema rung of Knowledge.
Taxonomy
The classification scheme — the layer list, the role list, and the rules for dropping things into them. Flat vocabularies. Lives in Dimensions.
Instance
A real thing in a customer's estate, resolved to a type id. A customer's estate is instances of the Schema.
Type id
Namespaced identifier minted from the Schema: aws_instance, data.aws_instance, ephemeral.x, children via /.
Containment
The contained_by edge. The hierarchy is the address and the diagnostic context — where a thing sits tells you what it depends on.
Placeholder node
Tier-4 node created when a support service references infrastructure the provider does not model. Evidence of unmapped infrastructure, waiting to be joined.
Skill registry
Third artefact alongside types.json and links.json: which skill may act on which type id with which verb. The agent's leash at the Action rung of Engagement.
Declared vs live
The boundary between Knowledge and Engagement. Terraform gives the map; it does not say the VM is powered off right now.
Fractal
The four Rungs repeat at every level of the Stack and every sublevel. One mechanism, many domains.
